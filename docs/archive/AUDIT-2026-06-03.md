### Блок E — `code_word` после approve (CRITICAL FIX)

**Root cause найден:** в `bot/handlers.ts` обработчик `cp:approve` шёл `if (r) { panel } else if (activateErr) { reply }`. Когда `funnel-activator` возвращал `null` БЕЗ ошибки (idea.strategy=null / bonus отсутствует / ChatPlace недоступен) — Юрию **ничего не приходило**. Поэтому и казалось «сейчас я этого вообще не наблюдаю».

**Применённые правки на VPS** (`src/bot/handlers.ts` lines ~340–540):

1. **Fallback path:** если `activateFunnelOnApprove` вернул `null` без throw — генерим code_word ad-hoc, делаем INSERT в `funnels` со status=`draft`, отправляем panel с пометкой «ChatPlace pending». Юрий ВСЕГДА получает code_word после approve.
2. **Catch-all:** если даже fallback не сработал — отправляется явное сообщение «⚠️ Воронка не активирована (причины: idea.strategy null / bonus отсутствует / ChatPlace недоступен)».
3. **Новый формат panel** (Markdown, разбит на 2 сообщения):
   - 🎯 *ВОРОНКА АКТИВНА*
   - Статус ChatPlace (active / pending / draft)
   - 🔤 Кодовое слово в моноширинном блоке (`KLUB_OFFICE_190` — клик копирует)
   - 📸 Все слайды списком с URL'ами (1. URL / 2. URL / …)
   - 📝 Подпись для Instagram между «————»
   - 📊 *КАК РАБОТАЕТ ВОРОНКА* 7-шаговая инструкция
   - Кнопки: 📋 Кодовое слово / 📋 Подпись / 📥 Скачать ZIP / ✅ Опубликовал
4. `sendMessageRaw` теперь принимает `parseMode` параметр.

Build ✅, pm2 restart ✅. Готово к тесту с любым новым approve.
